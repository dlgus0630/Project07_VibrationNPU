# Vivado/Vitis 2024.2에서 ARM 앱 실행

Basys 3 프로젝트에는 Vitis가 필요 없다. Fourier 프로젝트의 내장 ARM CPU 앱에는
Vivado 외에 **Vitis 2024.2 Embedded Development**가 필요하다.
이 문서는 Vitis Unified IDE의 platform/application component 흐름을 사용한다.
구형 XSCT `app create` 스크립트나 Classic workspace를 전제로 하지 않는다.

1. MATLAB Online 및 XSim을 통과한 뒤 `python tools/run.py build`를 실행한다.
2. `reports/fourier/fourier.xsa`가 생성됐는지 확인한다. XSA는 2024.2의
   `write_hw_platform -fixed -include_bit`로 내보낸다.
   [AMD 2024.2 명령 문서](https://docs.amd.com/r/2024.2-English/ug835-vivado-tcl-commands/write_hw_platform)
3. Vitis 2024.2를 열고 프로젝트 밖의 짧은 영문 경로에 workspace를 만든다.
4. Platform Component를 만들고 Hardware Design으로 위 XSA를 선택한다.
   processor는 `ps7_cortexa9_0`, OS는 `standalone`을 선택한다. platform을 build한다.
5. 해당 platform/domain으로 Empty Application Component를 만든다.
6. 다음 네 파일만 application의 소스 폴더에 넣는다: `main.c`, `golden.c`, `golden.h`, `model_data.h`.
   **host_check.c는 PC 검사용 별도 main 함수이므로 ARM 앱에 넣지 않는다.**
7. template의 기본 main/hello-world 파일이 있으면 앱 소스에서 제외해 main 중복을 없앤다.
   application을 build한다. BSP의 stdin/stdout이 보드의 USB-UART에 연결된 PS UART인지 확인한다.
8. Zybo를 JTAG 부팅으로 두고 USB-JTAG/UART를 연결한다. UART terminal은 115200, 8 data bits,
   no parity, 1 stop bit, no flow control로 설정한다.
9. application의 하드웨어 Run/Debug 설정에서 FPGA programming과 **PS initialization**을 포함한다.
   PS 초기화는 DDR와 FCLK0를 준비한다. Vivado로 bitstream만 쓰는 것으로 ARM/DDR/FCLK 초기화가 끝나지 않는다.
10. 다운로드·실행 후 시작 문구를 확인하고 `r`을 보낸다.

초기 replay는 센서를 연결하지 않아도 실행한다. 두 `RESULT` 줄에서 `match=1`이어야 한다.
그다음 `i`로 센서를 초기화하고 `s`로 입력 한 window를 추론한다.

모터 구동은 ARM 명령과 독립된 보드 스위치로 조작한다. 초기 replay에서는 SW0=OFF로 둔다.
배선 확인 후 SW2..1로 듀티를 정하고 SW0 OFF→ON으로 arm한다.
`s`/`d` 완료가 모터 정지를 뜻하지 않는다. SW0 OFF 또는 BTN0로 정지한다.
구체적인 배선과 듀티 표는 [HARDWARE.md](HARDWARE.md)를 따른다.

| 명령 | 기능 |
|---|---|
| r | 제공된 normal/fault 입력 각각 CPU·PL 실행 |
| b | 100회 replay, timing·일치 결과 출력 |
| i | MPU-6500/9250 ID 및 설정 검사 |
| s | sensor window 수집 후 CPU·PL 비교 |
| d | raw sample 64개와 관찰 간격 출력 |
| f | warning·derated·latch·watchdog·fault cause·누적 이상 수 출력 |

확장 펌웨어는 UART를 nonblocking으로 확인하면서 AXI `0x48`에 100 ms마다 heartbeat를 기록한다.
PL watchdog timeout은 500 ms다. 모터가 arm된 상태에서 ARM 실행이 멈추면 UART 명령 여부와 무관하게
PL이 출력을 latch 차단한다.

로컬 Python UART logger 예시:

```text
python tools/monitor.py --port COM5 --command r --seconds 5
python tools/monitor.py --port COM5 --command i --seconds 5
python tools/monitor.py --port COM5 --command s --seconds 5 --output reports/sensor.csv
```

다른 terminal이 COM 포트를 열고 있으면 먼저 닫는다. 펌웨어 상태는 logger를 닫아도 보드에서 유지된다.
logger 기본 경로는 매 실행 덮어쓰므로 보존할 측정에는 다른 `--output` 이름을 지정한다.
PC timestamp는 센서 내부 sample timestamp가 아니다.

## 주소와 결과 해석

control base `0x43C00000`, BRAM base `0x40000000`, 크기 각 4 KiB.
Block Design Address Editor와 펌웨어의 두 상수를 반드시 함께 확인한다.
PL은 100 MHz 설정, ARM은 Digilent board preset이 정한 주파수다.
펌웨어는 global timer의 BSP `COUNTS_PER_SECOND`로 CPU 시간과 end-to-end 시간을 환산한다.

출력 형식:

```text
RESULT,source,class,cpu_us,pl_cycles,npu_cycles,e2e_us,match,f0,f1,f2,f3,h0,h1,h2,h3,o0,o1
```

표시한 class는 C Golden class이며 `match=1`일 때만 PL 결과와 일치한다.
`pl_cycles/100`은 PL 계산 us, `cpu_us`는 CPU의 FFT+MLP 계산 시간,
`e2e_us`는 BRAM 입력 쓰기·START·polling·결과 읽기와 비교를 포함한다.
UART 출력은 측정 구간 밖이다. ARM D-cache는 BRAM 일관성을 단순화하려고 껐다.
따라서 캐시를 최적화한 ARM 대비 최고 성능이나 고유한 NPU speedup이라고 주장하지 않는다.

PL timeout이면 먼저 PS init/FCLK/reset, 주소, BD validation, BRAM addressing을 확인한다.
ID 0x00/0xff이면 전원·CS·MISO 배선을 먼저 확인한다.
다른 ID이면 그 센서용 driver·설정으로 별도 검증해야 하며 ID 검사만 제거하지 않는다.

ARM 앱과 FSBL은 Vitis 2024.2의 `ps7_cortexa9_0` standalone BSP로 컴파일·링크했다.
2026-09-12에 Zybo JTAG 다운로드, PS/DDR/FCLK 초기화, AXI/BRAM 접근과 UART replay를 확인했다.
센서 SPI와 모터 출력은 실제 부품 배선을 확정한 뒤 별도로 확인해야 한다.
